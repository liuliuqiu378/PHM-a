前面 0~5 层把「算法」讲透了，但 PHM 真正落地的难点往往**不在算法**，而在
系统工程与数据闭环。你问的几个问题——采集、传递、部署在哪、怎么传、怎么训练、
异常样本怎么建、异常识别有多难——正是决定「能不能上线」的分水岭。本模块把它们
系统化讲清，并补一个能跑的**无监督异常检测** demo 回应「异常样本稀缺」。

> 一张图先建立全局：算法只是 ①~⑥ 链条里的一环，红字是每个环节真实会踩的坑。

![PHM 工程全生命周期](figures/illustrations/phm_lifecycle.png)

## 1. 数据采集（最容易被教科书忽略的第一步）
- **采样率选型**：按奈奎斯特 + 关心的最高故障频率。轴承 BPFI≈162Hz 理论上 >324Hz 即可，
  但**冲击是宽带**的，要捕住瞬态需更高（CWRU 用 12k/48k）。采低了故障特征直接丢。
- **传感器选型与布置**：加速度计（IEPE）、转速、温度、油液、电流…多源融合比单振动可靠；
  测点离故障源远 → 信噪比差，信号被结构传递衰减。
- **标定与数据质量**：灵敏度漂移、丢点、饱和、量程选错；**时钟同步**（NTP/PTP）与多传感器
  时间对齐决定了能不能做时域联合分析。
- **真实坑**：传感器本身失效常被误判成「设备异常」——要把「传感器健康」和「设备健康」分开监控。

## 2. 数据传递 / 传输
- **协议**：边缘→云常用 MQTT（轻量 pub/sub）、OPC-UA（工业标准、带信息模型）、Kafka（高吞吐）。
- **压缩**：原始波形极大，边缘先做降采样/提特征再传，带宽能省一两个数量级。
- **断网缓存**：工厂网络不稳，边缘要本地缓冲、网络恢复后续传，否则丢关键片段。
- **时序对齐 + 时钟同步**：跨设备/跨传感器的时间基准不一致，分析全错。
- **安全**：加密、认证、OT 网络隔离（别让办公网直连产线）。

## 3. 模型部署在哪：端侧 vs 云侧（没有标准答案，看约束）
| 维度 | 端侧（MCU/网关） | 云侧 |
|---|---|---|
| 延迟 | 极低（本地） | 受网络 |
| 隐私 | 数据不出厂 | 数据上云 |
| 算力 | 受限（跑不了大模型） | 充足 |
| 更新 | OTA 麻烦 | 易迭代 |
| 断网 | 仍可用 | 失效 |

**主流是混合**：边缘做实时初筛/低延迟推理，云做训练、重训、复杂分析与全局看板
（见 `docs/05_system.md` 部署架构图与 `phm_lifecycle` 图的回环）。

## 4. 如何传输
- 不是什么都传原始波形：**边缘预处理后只传特征 / 健康分 / 告警**，省带宽也降敏。
- 带宽成本、电池供电设备的能耗都要算进架构。
- **模型下发 OTA**：版本管理、灰度发布、可回滚——模型上线和 App 一样要这套。

## 5. 模型训练与数据闭环
- **离线训练只是开始**：持续学习 / 数据闭环才是常态（新工况、新机型持续进来）。
- **标签稀缺**：谁打标？领域专家，成本极高 → 用**主动学习**挑最有价值的样本让人标，
  而不是全量标。
- **概念漂移**：季节、负载、原料变了，模型悄悄退化 → 要做**输入分布漂移检测** + 定期重训。
- **模型自身健康**：监控输入分布、告警率突变，防止「模型挂了没人知道」。

## 6. 异常样本的建立（你点出的最大缺口）
现实里：异常极少、甚至无标签、且很难定义「正常边界」。三种工业解法：
1. **无监督 / 单类（本模块 demo）**：只用正常数据训练自编码器，重构误差大即异常，
   故障样本完全不进训练。
2. **仿真注入故障**：用数字孪生 / 物理仿真生成异常样本（呼应场景 C/D 的仿真路线）。
3. **主动学习 + 专家标注**：先无监督圈出可疑，再让人确认，逐步积累有标签异常。

> 无监督异常检测 demo 结果（CWRU，仅 Normal 训练）：

![无监督异常检测 Overview](figures/engineering/anomaly_overview.png)

| 指标 | 值 |
|---|---|
| 训练数据 | 仅 Normal 类（140 窗口），故障 0 条 |
| AUC | 1.000 |
| 误报率（正常判异常） | 0.05 |
| 检出率（故障判异常） | 1.000 |

**必须讲真话**：AUC=1.0 是因为 CWRU 故障冲击极其明显、且数据干净。真实现场异常往往
**隐蔽、渐进、与工况耦合**，AUC 远不会这么高；而且无监督方法只能报「异常」，**不能区分
「哪种故障」**——要细分还得回到有标签数据（场景 A 的分类器）。所以工程上通常是
「无监督先抓异常 → 有标签再细分」两段式。

## 7. 异常识别有多难（远比分类精度显示的难）
- **开集 / 未知故障**：训练时没见过的故障类型，分类器会乱判。
- **代价不对称**：安全关键场景漏报代价 ≫ 误报，阈值要往「少漏报」调，但误报多又会被运维无视。
- **可解释性**：运维不信任黑箱，要能说清「为什么报警」（哪个频段、哪路传感器异常）。
- **传感器失效 vs 真实故障**：两者表现相似，要能区分（回到第 1 节）。

## 8. 你还想不到、但现场要命的
- **系统集成**：告警要落进 SCADA / CMMS / 维修工单才有用，否则只是个看板。
- **合规 / 隐私 / 数据安全**：产线数据出境、审计留痕。
- **灰度发布与责任归属**：模型建议停机，谁拍板？可审计、可回溯是硬要求。

## 9. 可运行 demo：边缘-云数据管线（传什么 / 怎么传 / 断了怎么办）
用合成振动流（健康 → 渐变退化 → 持续故障）把「采集→边缘→云」整条链路跑通，
直接回答你提的三个工程问题。对应 `src/module_06_engineering/edge_cloud_pipeline.py`。

![边缘-云数据管线实测](figures/engineering/edge_cloud_pipeline.png)

**① 传什么？** 边缘**不传原始波形**，只传「特征 + 健康分 + 告警」。本 demo 每窗口从 512
点原始振动提 12 维特征（RMS / 峭度 / 峰值 / 频谱质心 / 高频能量比 …），心跳包只带 3 个数，
完整特征按节流（每 8 窗一次）或告警时必传。

**② 怎么传？** MQTT 风格分层 topic：`plantA/pump-01/telemetry`、`.../alert`，pub/sub
解耦端云。脚本用本地 `LocalMQTTBroker` 仿真（支持 `+`/`#` 通配符），**生产环境把这一层
换成 `paho-mqtt` + Mosquitto/EMQX 即同等架构**——上层逻辑一行不动。

**③ 断了怎么办？** broker 离线时 `publish` 返回 `False`，边缘把 payload 塞进本地缓存；
网络恢复后**补传**，关键片段零丢失（demo 里第 90~100 窗模拟断网，恢复后补传 10 条）。

**④ 云侧收敛成工单**：持续告警用「带冷却迟滞」状态机收敛成**每次故障事件一张工单**，
而不是刷屏。

实测（240 窗口，FS=12kHz）：

| 项 | 值 |
|---|---|
| 若直传原始波形 | 960.0 KB |
| 实际只传特征/告警 | 42.8 KB |
| **带宽节省** | **22.4×** |
| 断网缓存 | 10 条，恢复后全补传，0 丢失 |
| 生成工单 | 1 张（单次故障事件） |

**必须讲真话**：22× 是 demo 合成流的数字——生产里「完整特征」不一定每 8 窗传一次，
心跳频率、QoS、 retained 消息、JSON vs 二进制（Protobuf/CBOR）都会改带宽；但「**特征化
后比原始波形小一两个数量级**」是铁律。另：本 demo 的「健康基线」用前 60 窗假设为健康—
真实要先有确认的健康期，或离线标定基线。

## 10. 可运行 demo：概念漂移 + 主动学习闭环（数据闭环的核心）
你点出的最大缺口「模型训练 / 数据闭环」用代码跑通。对应
`src/module_06_engineering/drift_active_learning.py`。

![概念漂移 + 主动学习](figures/engineering/drift_active_learning.png)

**① 概念漂移（上线≠结束）**：真边界在部署期旋转 38°（工况变化）。左图黑虚线「永不重训」
误差从 ~0 一路爬到 **0.25**——模型静默退化、自己还以为很准（置信度虚高）。这正是现场
最危险的情况：**没人知道模型已经烂了**。

**② 主动学习闭环**：模型监控自身「不确定度」（预测概率离 0.5 越近越拿不准）。滚动不确定度
超基线即判定「漂移来了」，挑**最不确定**（边界附近）的样本请专家打标，滑动窗口增量重训
（只保留最近 48 条，忘掉已漂移的旧工况，避免旧数据把边界拉回）。

**③ 三种策略实测（同一数据流，每轮 4 个标签）：**

| 策略 | 末点误差 | 说明 |
|---|---|---|
| 永不重训 | 0.250 | 持续恶化，灾难 |
| 随机采样重训 | 0.050 | 能恢复 |
| **主动学习（挑最不确定）** | **0.025** | **同样标签数，误差只有随机的一半** |

右下图直观：主动学习只把「边界附近最不确定」的样本（黑圈）送专家，用最少的标签把
旋转的边界追回来。

**必须讲真话**：
- 本 demo 用 2D 线性边界（Logistic 回归）直观可视化；真实 PHM 套同框架——用模型
  预测熵/置信度做漂移哨兵，用不确定性采样挑样本，滑动窗口或持续学习做增量重训。
- 主动学习的前提是**有专家能打标且愿意打**——延迟、成本、专家可用性都是真实约束；
  工业上常和「无监督先圈可疑」（模块 6）配合：无监督发现异常 → 主动学习优先标这些。
- 「概念漂移」还有**协变量漂移**（特征分布变、边界不变，如换了同型号传感器），检测与
  应对不同，demo 只演示了概念漂移这一种。

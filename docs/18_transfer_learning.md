# 迁移学习 / 域适应：为什么"一台机器训的模型到另一台就掉点"

> 接 [`03_诊断`](./03_diagnosis.md)（RF 0.977→0.673 跨工况暴跌）与 [`08_方法总图谱`](./08_method_landscape.md)。
> 这是工业 PHM **最真实、最常被追问** 的问题：实验室 99%，现场一上就拉胯。本文讲清**为什么会掉、怎么救**，并给一个可跑 demo。
> 可跑脚本：`src/module_03_diagnosis/demo_domain_shift.py`（合成域偏移，一张图 + 两个准确率）。

## 1. 现象：从 0.977 到 0.673 说起

[`03_诊断`](./03_diagnosis.md) 里同一个 RF，换一种**评测协议**结果天差地别：

| 协议 | RF（物理特征）准确率 | 含义 |
|---|---|---|
| 窗口级（同文件/同工况） | **97.7%** | 训练和测试来自同一段录音、同一负载 → 乐观 |
| 文件级（跨工况） | **67.3%** | 训练/测试来自**不同文件、往往不同负载** → 贴近现场 |

1D-CNN 也是 92.6% → 73.0%。**两者换负载后都大幅掉点**——这不是模型差，是**分布变了**。

> 一句话：**评测协议决定结论**。窗口级会把"同一段录音切两半"当训练/测试，模型其实早就见过同类数据 → 高估。真现场永远是要"在没见过的机器/工况上"判病。

---

## 2. 为什么会掉：根因是"分布偏移 (Covariate Shift)"

模型学的是 `P(标签 | 特征)`。跨机器/跨工况时，**特征本身的分布 `P(特征)` 变了**，但"特征→标签"的规律没变。于是源域训好的决策边界，到目标域就切歪了。

### 2.1 工况变化（负载 / 转速）
同一轴承点蚀，在**轻载**和**重载**下：
- 振动**绝对幅值**不同（重载整体幅值放大）；
- 噪声底不同；
- 调制边带相对强弱不同。
→ 你用"峭度/RMS/包络峰**绝对大小**"当特征，重载域整体右移，源域阈值失效。

### 2.2 设备个体差异（最坑）
同一型号两台机器：
- 传感器**安装位置/力矩**不同；
- 齿轮/轴承**出厂间隙、动平衡**微小差异；
- **传递路径 (FRF)** 不同 → 同一故障在信号上被不同"滤波"。
→ 哪怕同负载，两台机的振动谱也不完全一样。这是"同一型号也掉点"的主因。

### 2.3 评测协议自己骗自己
窗口级划分 = 同文件内切分 → 训练和测试**同工况、同传路径** → 当然高。掉点被" protocol "藏起来了。

### 2.4 demo 一眼看懂

![域偏移 demo](figures/diagnosis/domain_shift_demo.png)

左：用**绝对幅值特征(RMS)**，机器 A（load=1）和机器 B（load=2.2）的两类分布明显**错开**；在 A 上训的阈值到 B 全错 → 跨域 **50%**（等于瞎猜）。
右：改用**归一化特征(峰值/RMS)**，两个域的分布**基本重叠** → 跨域 **99.9%**（救回）。

> 这就是掉点的本质：**绝对量随负载/机器漂移；相对量（比值）负载无关**。

## 3. 域适应 / 迁移学习在干什么

目标只有一个：**让源域和目标域在"特征空间"里对齐**，或者**直接学一个域不变的特征**。两大类思路：

| 思路 | 做法 | 需目标域标签？ |
|---|---|---|
| **特征归一化 / 物理特征** | 把绝对量变成相对量、用负载无关的物理量 | 不需要 |
| **分布对齐（域适应）** | 显式把两域特征分布拉近 | 多不需要（无监督域适应） |
| **微调 / 迁移** | 源域预训练，目标域少量标签 fine-tune | 需要少量 |

---

## 4. 怎么解决（方法谱系，从便宜到贵）

### ① 数据层：先别急着上算法
- **多工况/多机采集**：源域就覆盖多种负载、几台机器 → 模型天然见过变化；
- **数据增广（域随机化）**：训练时对信号做**加噪、幅值缩放、变速重采样** → 等价于"模拟不同机器"，低成本提泛化；
- **收集目标域无标签数据**：域适应大多只需要"无标签"目标数据（现场最容易拿到）。

### ② 特征层：归一化 + 物理特征（PHM 独门优势）
- **幅值归一化**：RMS 归一、按转频归一、包络能量占比（本教程 demo 的"峰值/RMS"就是这类）；
- **用负载无关的*频率*特征**：BPFI/BPFO/BSF/FTF 这些**故障特征频率**，只要转速相同就**固定不变**——幅值会变，但"在 162Hz 有没有尖峰"是负载无关的（[`09`](./09_fault_sensor_map.md)）。这就是为什么 PHM 里**物理特征做冷启动特别稳**：它自带域不变性。
- 代价：绝对幅值仍含信息（重载下故障更明显），归一化会丢一点敏感度 → 工程上常"归一化特征 + 少量目标域微调"组合。

### ③ 分布对齐算法（域适应）
- **MMD / CORAL**：在特征层加一个"源域和目标域分布距离"的损失，训练时一并最小化 → 强迫特征对齐；
- **对抗域适应 DANN**：特征提取器 vs 域判别器**对抗**——判别器想分辨"这特征来自哪台机器"，提取器想骗过它 → 最终提取出"分不出机器、但能分故障"的表示；
- **自训练 / 伪标签**：源模型给目标域打伪标签 → 再拿去训练 → 迭代修正（简单有效，工业常用）。

### ④ 微调 / 迁移学习（有少量目标域标签时）
- **预训练 → 微调**：源机大数据预训练，目标机**少量标签** fine-tune（冻结前几层、只训后面）；
- 对应 [`07_工程实战`](./07_engineering.md) 的**主动学习**：挑目标域里"最不确定"的样本请专家标，用最少标签完成适配。

### ⑤ 无监督异常检测天然跨机（最省事）
[`07`](./07_engineering.md) 的 AE 只在**正常数据**上训，目标机直接看"重构误差超阈"。只要两台机器"正常"的分布接近，这个方法**几乎不需要适配**——因为它不学"哪类故障"，只学"正不正常"。代价：只能报异常、不能分类型。

### ⑥ 组合拳（教程推荐）
> **物理特征冷启动（负载无关、可解释） + 深度学习精细化（学更复杂表示） + 目标域少量数据微调/主动学习。**
> 这正是 [`03`](./03_diagnosis.md) 第 3.5 节那句"用物理特征做冷启动 + 用深度学习做精细化"的工程落地。

## 5. 怎么评测才不骗自己

- **必须跨文件 / 跨工况 / 跨机**验证，绝不只报窗口级；
- 报指标时**同时给"源域内"和"跨域"两个数**，掉点幅度本身就是价值（如 RF 97.7%→67.3%）；
- 像 [`04_预测`](./04_prognostics.md) PHM2025 那样**按设备留一法 (Leave-One-Engine-Out)**，比随机切分严得多。

## 6. 面试怎么讲这个 0.977→0.673

> "RF 在同工况下 97.7%，但**跨工况掉到 67.3%**——因为手工特征（峭度/RMS）是**绝对量**，会随负载和机器个体漂移（分布偏移）。根因有两层：**工况变化**让幅值整体变、**设备个体差异/传递路径**让同一故障信号表现不同。
> 解决我分三档：最便宜的是**特征归一化 + 用负载无关的故障频率特征**（BPFI 频率固定，幅值才变）；要更稳就上**域适应**（MMD/对抗训练把两域特征对齐，大多只需目标域无标签数据）；有少量目标域标签就**微调 + 主动学习**。我们教程里无监督 AE 还能天然跨机——因为它只学'正不正常'。关键教训是：**评测必须跨工况，否则 99% 是假象**。"

这段话把"现象→根因→三档解法→诚实边界"一次讲清，且每个点都能指回教程章节。

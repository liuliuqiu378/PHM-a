# 行业专业知识：为什么 PHM 落地是真壁垒

> 上篇 [`10_故障机理`](10_fault_mechanism.md) 讲了"机器怎么坏"。但懂机理只是**技术入门**。
> 真正让 PHM"能干、敢用、值钱"的，是这套**行业认知**：维护怎么演进、标准怎么说、老板关心什么、现场为什么不信告警。
> 这部分教科书很少讲，却是工程里最硬的壁垒——也是面试/和客户对话时"像内行"的分水岭。

## 1. 维护策略的四级跳（行业的来时路）

维修不是一开始就有 PHM。它随时间一步步进化：

| 级别 | 策略 | 大白话 | 代价 | 典型场景 |
|------|------|--------|------|----------|
| L0 | **事后维修** Corrective | 坏了再修 | 非计划停机损失最大、常连锁损坏 | 不重要的设备、备件便宜 |
| L1 | **定期维修** Preventive | 到时间/里程就修（不管坏没坏） | 过修浪费 + 仍可能突发 | 汽车保养、定检 |
| L2 | **状态/预测维修** CBM/PdM | 看状态决定修不修、何时修 | 省停机、省过修，但需监测体系 | 风电、石化、航空 |
| L3 | **处方性维修** Prescriptive | 预测 + 结合成本/备件/排程给出**最优决策** | 全局最优，但组织/数据要求高 | 少数头部企业 |

> 关键认知：**不是所有设备都值得上 PHM**。用 **RCM（以可靠性为中心的维修）** 按"关键性×故障后果"分级——
> 一台冷却风扇坏了无所谓，一台主轴承坏了全厂停。PHM 资源要压在"坏了代价大"的设备上。

## 2. 标准体系：行业的"普通话"

讲出去像内行，得知道这套 ISO 谱系（不用背号，知道各自管什么）：

| 标准 | 管什么 | 和本教程的对应 |
|------|--------|----------------|
| **ISO 17359** | PHM 通用指南（怎么起步） | 总纲 |
| **ISO 13374** | PHM 数据处理流程链：采集→特征提取→健康评估→预测→决策 | **几乎一一对应本教程分层** |
| ISO 13372 / 13379 / 13381 | 术语 / 诊断推理框架 / 预测方法 | 概念层 |
| **ISO 10816 / 20816** | 振动烈度评级（机器分族，A/B/C/D 区） | 现场判"振算不算大"的尺（`09` 传感器之外的判定尺） |
| ISO 18436 | 人员认证（振动分析师等级） | 人 |
| **SAE JA6268 / JA8720** | 航空 PHM 设计者指南 | 航空口径 |

> 类比：标准是"行业普通话"。客户、审计、验收都认它。你说"按 ISO 10816 的 C 区报警"，
> 比说"振动超过 4.5 mm/s 就告警"可信得多——因为前者是**全行业校准过的尺度**。

## 3. OEE 与停机成本：讲给老板听的语言

技术人爱讲"准确率 97%"，老板只关心一件事：**少停几次、少花多少钱**。

- **OEE（设备综合效率）= 可用率 × 性能 × 质量**。PHM 主要提升"可用率"（少非计划停机）。
- **一次非计划停机的真实代价** = 产能损失 + 紧急抢修费 + 连锁停工 + 交期违约，往往**远大于**监测系统的投入。
- PHM 的 ROI 公式不是"模型多准"，而是：
  `省下的停机损失 + 省下的过修成本 − 系统+标注+运维成本`。

> 举例（量级感受，非精确）：一台风电机组非计划停机一天，损失可能是几万；
> 一条电池产线停几小时，损失可能是百万级。**一个提前两周的预警，价值就是一次计划性停机 vs 一次紧急抢修的价差。**

## 4. 告警疲劳与"异常 ≠ 可行动"（现场第一坑）

这是 `07` 反复点到的真问题，单独展开：

- **告警疲劳**：误报多了，运维直接当没看见——系统越灵敏反而越被忽略。
- **代价不对称**：漏报（没报）→ 出大事；误报（乱报）→ 被嫌弃。两者代价不同，阈值不能简单取中间。
- **"异常"不等于"要修"**：模型说"振动异常"，只是"信号不对劲"。要变成工单，必须回答三件事：
  1. **是什么故障模式**（轴承？齿轮？）——否则维修工不知带什么件；
  2. **还剩多久**（RUL）——否则不知急不急；
  3. **业务影响多大**（这设备停了产线停不停）——否则不知优先级。

> 这正是 `07` 里"云侧把持续告警收敛成每次故障一张工单"的工程意义：
> **把一串异常，翻译成现场能执行、可信赖的一个动作**。这一步比模型本身更决定系统是否被用。

## 5. 真壁垒在哪（为什么不是调包就能干）

很多人以为 PHM = 训个模型。错了。模型是**最容易**的那环。真壁垒在四周：

| 壁垒 | 是什么 | 为什么难 |
|------|--------|----------|
| **数据壁垒** | 故障样本极稀缺、标注贵、需领域专家；工况多变、常无标签 | 无监督/主动学习（`07`）是被这逼出来的 |
| **机理壁垒** | 现场只信"能解释"的结果；黑箱没人敢据此停机 | 懂 `10` 的机理才能定阈值、服众 |
| **系统集成壁垒** | 告警要真进 SCADA/CMMS（如 Maximo）建工单 + **人确认** | OT/IT 隔离、协议、安全、流程 |
| **组织壁垒** | 维修责任、SOP、变革管理；算法结果要变成被采纳的工单 | 比技术更难，常是项目死因 |
| **长期运维壁垒** | 模型会漂移（`07`），需持续重训、版本管理、可回滚 | MLOps，不是"训一次完事" |

> 一句话总结壁垒：**真正值钱的，是"把算法结果变成现场可信赖、可执行的决策"这一整层，不是模型本身。**

## 6. OEM  vs  第三方 / PHM  vs  HM

- **OEM（原厂）**：有设计数据、机理细节，但**封闭**、绑定自家设备；
- **第三方（独立供应商）**：跨品牌、中立，但**缺内部机理**，靠数据补；
- **PH（Prognostics，预测）vs HM（Health Management，健康管控）**：前者回答"还能跑多久"，后者是"从监测到决策的全寿命管理"。本教程两者都覆盖（诊断+预测+工程闭环）。

## 7. 面试/讲解的"一句话定位"（背这句）

> **PHM 不是算法竞赛，是"机理 + 数据 + 工程 + 组织"的系统工程；模型只是其中一环。**
> 懂机理能选对传感器、懂数据能训模型、懂工程能落地、懂组织能让结果被用——四者缺一不可。

把这话讲出来，比罗列十个模型更有"真入门、真壁垒"的味道。
